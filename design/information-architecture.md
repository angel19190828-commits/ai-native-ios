# 信息架构 · "目标任务空间"

## 1. 定位

"目标任务空间"不是新 App,是系统在识别到"当前信息里有一个可执行目标"时生成的**系统级任务界面**。它可以从邮件、信息、日历邀请等任何承载"事件类内容"的界面被唤起,承载同一个任务从识别到完成的全过程。

## 2. 核心数据模型

一个任务(Task)由以下部分组成,贯穿本项目全部线框图与原型:

```
Task
├─ goal                用户目标(如"帮我准备这次面试")
├─ sourceContent        触发内容(邮件全文 + 发件人 + 时间)
├─ extractedInfo[]       提取出的关键信息条目
│   ├─ label            字段名(日期/时间/地点/联系人/材料…)
│   ├─ value             当前值
│   ├─ source            来源(如"来自 Alex 的邮件,第 1 行")
│   ├─ confidence        certain | ambiguous(需用户确认)
│   └─ editable          是否可编辑
├─ steps[]               任务计划中的步骤
│   ├─ title             步骤名称
│   ├─ app               使用的系统功能/App(日历/地图/提醒事项/文件/信息)
│   ├─ source             该步骤依据的信息条目
│   ├─ risk               low | medium | high
│   ├─ needsConfirmation  是否需要确认(由风险等级派生,high 必须单独确认)
│   ├─ status             pending | preparing | waiting_confirmation | done | failed | cancelled
│   └─ result             执行结果摘要 / 失败原因
├─ conflicts[]            检测到的日程冲突
└─ overallStatus          待处理 | 正在进行 | 等待确认 | 部分失败 | 已完成 | 已取消
```

## 3. 风险分级(贯穿所有交互)

| 等级 | 定义 | 本场景中的步骤 | 确认方式 |
|------|------|----------------|----------|
| 低风险 | 查看信息、查找文件、计算路线 | 查看路线、查找作品集候选 | 可自动准备结果,无需逐条确认 |
| 中风险 | 创建日历、创建提醒、修改日程 | 创建面试事件、设置出发提醒、设置准备提醒 | 执行前确认,或在统一计划确认中批量确认 |
| 高风险 | 发送消息、取消预约、支付、分享敏感文件 | 向 Alex 发送改期消息 | 必须单独确认,不可被批量确认覆盖 |

## 4. 系统级入口(同一任务的多处呈现)

依据 [01-system-audit.md](../research/01-system-audit.md) 的七类入口审查,"目标任务空间"不是独占一个界面,而是在以下位置提供同一任务状态的不同切片:

| 位置 | 展示内容 | 交互深度 |
|------|----------|----------|
| 邮件内的系统建议入口 | "这封邮件包含一个需要准备的面试事件" | 点击进入完整任务空间 |
| 锁屏 / 实时活动 | 当前阶段 + 下一步提示(如"距出发还有 40 分钟") | 只读 + 一个主要操作 |
| 通知 | 需要确认的单条操作(如冲突提醒) | 展开/确认/忽略 |
| 主屏幕小组件 | 任务整体进度条 + 下一步 | 点击进入任务空间 |
| Siri / 系统搜索 | "面试任务"作为可搜索、可语音查询的结果 | 语音播报状态,点击进入 |

## 5. 信息架构图(文字版)

```
邮件 App(触发点)
   └─ 系统级 AI 建议入口
        └─ 目标任务空间(核心界面,系统级,非独立 App)
             ├─ 信息提取与确认
             ├─ 任务计划(步骤列表)
             ├─ 批量确认 / 单独确认(高风险)
             ├─ 冲突处理分支
             ├─ 执行进度
             ├─ 失败恢复分支
             └─ 完成态(含撤销入口)
                  │
                  ├─ 持续投影到:锁屏 / 实时活动
                  ├─ 持续投影到:通知
                  ├─ 持续投影到:主屏幕小组件
                  └─ 可被查询:Siri / 系统搜索
```

## 6. 状态优先于导航

与传统 App 的"页面导航"不同,"目标任务空间"的信息架构以**任务状态**为主轴,而不是以"页面"为主轴——用户在锁屏看到的、在小组件看到的、在完整任务空间看到的,是**同一个 overallStatus 在不同容器里的呈现**,而不是三个独立页面。这是本项目与"再做一个 AI 邮件/日历 App"的关键区别(参见 [scope.md](../research/05-scope.md) §5.6)。
