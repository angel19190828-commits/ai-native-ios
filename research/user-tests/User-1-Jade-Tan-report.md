## 测试前行为背景

Jade 表示她会因目的不同使用 Siri、Calendar、Reminders 和 Shortcuts，但更偏好 Reminders。线上活动通常附带可直接加入 Apple Calendar 的链接，因此她很少手动录入。对于容易记住的单次活动，她倾向于先记在脑中，临近日期再返回邮件检查准备事项。线下面试需要规划通勤时，她通常会询问未婚夫，并在活动前 1–2 天安排。

> “I often take a mental note for individual events rather than saving them to Reminders or Calendar.”

> “I also revisit the email when the date draws closer to see if I need to prepare anything before hand.”

## 操作流畅度与核对行为

本报告不把静止或阅读时间直接当成困惑。只有以下组合信号才会标记：

- **停顿 + 回看来源**：可能是不确定，但需要回看行为支持
- **输入后撤回或修改**：可确认发生错误或重新判断
- **同一信息跨页面重复查找**：可确认存在记忆或上下文负担
- **搜索词连续细化**：可确认第一次查询没有直接达到目标
- **口头表达“不知道/不确定”**：本视频无有效音频，不能使用此证据

Jade 在整个过程中没有明显或持续的犹豫。她能够熟练地在 Mail、Reminders 与 Calendar 之间切换。日历时间从 10:00 修改为 10:30 更适合记录为一次轻微信息修正；返回邮件则符合她平时依赖邮件和 mentally remind 信息的核对习惯，不应解释为困惑。

## 屏幕与操作习惯

1. **以原始信息为中心**：邮件始终是可信来源；不确定时返回邮件，而不是依赖系统记忆。
2. **偏好结构化列表工具**：先使用 Reminders，再使用 Calendar，符合她访谈中对 Reminders 的偏好。
3. **习惯将一个目标拆进多个 App**：提醒、事件和路线分别进入不同工具，没有统一任务容器。
4. **使用系统搜索快速进入工具**：进入地图阶段时使用系统搜索，而非从主屏幕逐页寻找。
5. **边做边补信息**：先建立提醒和日历，再处理地址与路线；准备材料没有被纳入同一流程。
6. **重复录入可被接受，但会产生错误风险**：同一个事件在 Reminders 与 Calendar 中分别创建，时间信息需要再次输入和核对。

### App 内组件

| App | 实际使用的组件 | 作用与限制 |
|---|---|---|
| Mail | Inbox、邮件详情页、邮件正文；Summarize 入口可见但未确认点击 | 邮件是唯一信息源与复查来源；摘要能力没有转化为可执行任务 |

### 组件级结论

User 1 使用的是成熟且熟练的“App 内组件组合”：Mail 负责读取，Reminders 负责记事，Calendar 负责事件，Maps 负责通勤。系统级能力只在 Spotlight 启动 Maps 时短暂出现；Siri、Widget、Shortcuts、通知和 Live Activity 都没有承担任务连接或进度管理。
## 关键发现

### 1. 用户把邮件当作外部记忆

Jade 的访谈与录屏一致：她依赖“之后再回邮件看”，而不是一次性把所有信息整理到一个地方。邮件承担了系统本应帮助维持的上下文。

### 2. 当前工具能完成局部操作，但不能维护完整目标

Reminders、Calendar 和 Maps 都顺利完成了各自的局部任务，但系统没有提示“作品集尚未准备”，也没有统一显示整个面试准备状态。

### 3. 熟练切换仍需要用户自己维护信息一致性

Jade 能够顺利完成跨 App 操作，但同一信息仍需要在不同位置输入和核对。10:00 调整为 10:30 表明，即使操作流畅，信息一致性仍由用户自己维护。

### 4. 自动链接会影响用户是否手动规划

Jade 表示线上活动通常已有 Event link，因此几乎不会手动添加。线下、纯文本邀请才更容易暴露跨 App 组织问题，说明本项目选择的任务场景具有针对性。

## 设计机会（仅基于 User 1，待与 User 2 对照）

- 从邮件直接生成可编辑的任务草稿，减少重复输入
- 在创建前显示日期、时间和地址的来源，帮助发现提取错误
- 将日历、提醒、路线和材料准备放在同一任务状态中
- 对已执行操作和未完成事项提供清晰区分
- 当用户修改时间时，同步提示受影响的提醒和路线
- 保留“只添加到日历”等轻量出口，不强迫用户采用完整计划
