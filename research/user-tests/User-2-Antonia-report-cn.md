## 测试前行为背景

Antonia 表示她主要使用 Calendar 管理预约。如果邮件提供自动加入日历的选项，她会直接使用；如果没有，她会手动把信息加入 Calendar。

> “I use calendar for my appointments.”

> “If it has the option to add automatically to my calendar I do it, if not I add it manually to my calendar app.”

这说明她的行为模式不是拒绝自动化，而是优先采用现成的日历入口；缺少入口时，再自己完成信息搬运。

## 关于时间差异的记录

邀请时间为 10:30，录屏中的 Calendar 事件显示为 10:00–11:00。该差异可能是输入偏差，也可能是参与者主动预留提前到达时间。由于视频没有口述解释，本报告将其标记为：

> **信息存在差异，原因待确认。**

不能在没有追问的情况下直接写成“用户输入错误”。后续访谈应询问：

> “你把日历设置为 10:00，是为了提前到达，还是记错了邮件中的时间？”

## 操作与信息组织习惯

1. **以 Calendar 为主要任务中心**：收到预约后，第一反应是创建日历事件，而不是使用 Reminders 或 Siri。
2. **愿意使用自动入口**：如果邮件已有 Add to Calendar，她会直接采用；纯文本邀请才需要手动录入。
3. **跨设备完成后复查**：她会从手机 Calendar 回看电脑上的 Email 核对内容。这是谨慎的确认习惯，不应直接解释为犹豫。
4. **地图独立承担通勤计算**：地址和通勤时间没有与日历事件形成持续连接，需要单独进入 Google Maps。
5. **纸质便利贴承担准备提醒**：作品集要求没有进入 Calendar，而是保存到屏幕外的实体工具中。
6. **任务状态跨媒介分散**：时间在手机 Calendar、路线在手机 Maps、原始信息在电脑 Email、材料提醒在纸上。

### App 内组件

| App / 设备 | 实际使用的组件 | 作用与限制 |
|---|---|---|
| 电脑 Email | 邮件正文与原始邀请信息 | 提供可信信息源；与手机 Calendar 不在同一设备，需用户跨设备核对 |
| iPhone Calendar | 年/月/日视图、New Event、事件标题、日期选择器、开始/结束时间选择器、事件详情页 | 是 Antonia 的主要预约工具；所有信息仍需从电脑邮件手动搬运 |
| Google Maps | 地点搜索、地点结果卡片、Directions、当前位置、路线与通勤时间 | 自动计算约12分钟通勤，但不会回写完整面试准备状态 |
| 系统键盘 | 事件标题、联系人/文字、日期和时间输入 | 帮助录入，但没有验证邮件与日历是否一致 |
| 纸质便利贴 | 手写提醒“携带作品集” | 不是 iPhone 组件，但承担了系统未覆盖的准备提醒功能 |

### 组件级结论

User 2 几乎完全依赖 App 内组件：Calendar 负责预约，Google Maps 负责路线，电脑 Email 负责复查，纸质便利贴负责材料提醒。Siri、Widget、Shortcuts、通知和 Live Activity 都没有参与；这说明问题并不是缺少单个功能，而是现有组件之间没有共享一个可追踪的任务状态。
## 关键发现

### 1. 日历是她最信任的预约工具

Antonia 的访谈和录屏一致：她把 Calendar 当作预约的最终记录位置。自动添加入口可以显著减少手动录入，但纯文本邮件仍需要她自己搬运信息。

### 2. 跨设备复查不是不会使用，而是缺少信息同步确认

她能够顺利创建事件，没有明显操作障碍。她需要从手机转回电脑查看 Email，说明系统没有帮助她验证“手机日历中的内容是否与电脑邮件一致”，因此正确性仍由用户跨设备保证。

### 3. 完整目标跨越设备、App 与纸张

电脑 Email 保存原始邀请，手机 Calendar 和 Maps 处理时间与路线，“携带作品集”则被记录到纸质便利贴。当前系统无法把这些跨设备、跨 App、跨媒介的状态识别为同一个面试准备任务。

### 4. 单个 App 都能完成局部工作，但没有统一完成状态

Calendar 成功保存事件，Maps 成功计算通勤，便利贴成功保存材料提醒；然而没有任何一个界面告诉她：面试是否已经准备完整。

## 设计机会（基于 User 2，需与 User 1 综合）

- 从纯文本邮件直接生成可检查的日历草稿
- 创建前并排显示“邮件原文”与“系统提取结果”，支持快速核对
- 将路线、通勤时间和提前到达要求关联到同一事件
- 把“携带作品集”等材料要求转化为可追踪准备项
- 保留 Calendar 作为主要入口，不强迫用户进入新的独立 AI App
- 允许用户选择仅添加日历，或扩展为完整准备计划
