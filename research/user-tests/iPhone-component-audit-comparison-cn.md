# 两位用户｜iPhone 系统组件使用对照

> 数据来自两段手机录屏、访谈回答与主持人观察。样本量为 2，仅用于探索性方向，不代表普遍使用率。

| 组件 / 系统入口 | User 1 · Jade | User 2 · Antonia | 观察结论 |
|---|---|---|---|
| Mail / Email | iPhone Mail；邮件详情与正文，Summarize 入口可见 | 电脑 Email；作为原始信息与复查来源 | 两人都把邮件作为可信来源，但设备环境不同 |
| Calendar | 使用月/日视图、事件编辑、时间和 Alert | 作为核心工具，使用年/月/日视图及事件编辑 | **2/2 使用**，但均需手动搬运信息 |
| Reminders | 使用 New Reminder、日期和时间选择器 | 未使用 | Jade 倾向 Reminders；Antonia 以 Calendar 为中心 |

| Shortcuts | 未使用 | 未使用 | **0/2 使用** |
| 通知中心 | 未使用 | 未使用 | **0/2 使用** |
| Live Activity | 未使用 | 未使用 | **0/2 使用** |

## 组件层面的主要发现

1. **用户依赖 App 内成熟组件，不依赖 AI 系统入口。** 两位参与者都能完成 Calendar 和 Maps 的局部操作，没有明显操作困难。
2. **Siri、Widget、Shortcuts、通知和 Live Activity 没有连接任务。** 这些系统能力存在，但本次任务中没有成为自然路径。
3. **Calendar 与 Maps 是共同核心组件。** 两位用户都需要它们，但信息不能自动从邮件持续流向事件、路线与准备事项。
4. **系统搜索只解决“找到 App”，不解决“继续任务”。** User 1 使用 Spotlight 进入 Maps，但之前的邮件和日历上下文没有随之传递。
5. **系统之外的记忆仍然重要。** Jade mentally remind，Antonia 使用纸质便利贴，说明完整任务状态没有被任何单一组件承接。

## 对概念设计的直接影响

- 不需要再造 Calendar、Reminders 或 Maps 的基础组件
- AI 应出现在用户正在查看的邮件或系统入口中，而不是要求打开独立 AI App
- 生成的任务必须继续使用用户熟悉的日期选择、事件编辑、路线和提醒组件
- 系统层新增的价值应是共享上下文、统一状态、来源核对、确认和撤销
- Widget / Live Activity 可作为持续状态的后续出口，但不能假设用户会主动进入它们
